# T-002 — Target architecture

**Tier:** A (Fable · high) · **Size:** L · **Repos:** workspace, backend · **Milestone:** H0 · **Requires:** T-001

## Goal
Close the phase 1 domain tree and make it visible in the documentation site in state `planned`: it is the map against which all milestones are designed.

## Read first
- `docs/agent/SPEC_MAP.md` in full (especially §3, §21 and the responsibilities per topic).
- `docs/agent/DECISIONS.md` D-001 (initial proposal to confirm or correct).
- `docs/agent/GAPS.md`.
- `docs/definitivos/md/post_15_responsabilidades_y_limites_entre_dominios.md` and the "Técnico / dominios" section of `playhoot.md` (from `# Técnico / dominios`).
- `docs/agent/inventory/backend-domains.md` §0, §9, §10.

## Deliverables
1. `DECISIONS.md`: D-001 closed (definitive tree, with the reason for each new or moved domain and what was discarded).
2. Documentation data in `playhoot/docs/system/` for **each target domain and subdomain**: responsibilities, what it does not know, what it depends on (only via orchestrator/composer), specification sources, state (`implemented` for those that exist, `planned` for the rest).
3. **Flow catalog** of phase 1 in `planned`: name, coordinator, domains it touches and source; no detailed steps (the design of each milestone details them). It must cover all flows of the base and those that the patches add.
4. Shared packages that are not domains (queue, limits, storage, logs, metrics): listed and described where appropriate in the site.
5. Review of `PLAN.md`: confirm or adjust the order and content of H1–H13 in light of the tree; note new dependencies.

## Acceptance criteria
- Every responsibility of `SPEC_MAP.md` §4–§20 has exactly one owner domain in the site.
- The tree is a tree: no subdomain is used by anything other than its parent; no direct dependency between top-level domains.
- `node tools/validate-docs.mjs` at 0.
- If a decision at the level of "domains and their coordination" appears that materially changes the base's proposal, it is recorded as open question `C-NN` with a recommendation (P01§2); it does not block the rest.

## Out of scope
Tables, operations and flow steps (they belong to each milestone's design). Code.
