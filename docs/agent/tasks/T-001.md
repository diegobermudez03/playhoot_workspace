# T-001 — System documentation site

**Tier:** B (Opus · medium) · **Size:** M · **Repos:** workspace, backend, frontend · **Milestone:** H0

## Goal
Get the HTML site the creator will use to understand the system working, with all its views, plus the data validator. With enough seed data to exercise every view; the full load is done by T-002, T-004 and T-005.

## Read first
- `docs/agent/designs/system-docs.md` (the full specification: it is this task's contract).
- `docs/agent/METHOD.md` §7.
- For the seed data: `docs/agent/inventory/backend-domains.md` §3.2 (workflow `sessionlifecycle`), §3.5 (tables `play_sessions`, `play_session_join_codes`, `play_create_session_requests`), §6 (`playlifecycle.CreateSession`); `docs/agent/inventory/frontend.md` §2 (routes `/sessions/new`, `/sessions/:uuid/host`).

## Deliverables
1. `docs/system/index.html`, `app.js`, `style.css` in the workspace, per the specification §2–§4. Interface text in English.
2. `tools/validate-docs.mjs` per §5 (first stage: data integrity; coverage against the code is a separate task).
3. `playhoot/docs/system/manifest.js` + data files; `playhoot_frontend/docs/system/manifest.js` + data files.
4. Real seed data (status `implemented`), one complete end-to-end path: **create session** — screen `/sessions/new` → endpoint `POST /v1/sessions` → flow `playlifecycle.CreateSession` → operations `game.checkplayability` and `play.session.CreateSession` → their tables, with the session lifecycle. Plus the current domains at tree level (no detail): `api`, `orchestrator`, `composer`, `identity`, `game`, `play` (`session`, `runtime`).
5. Confirm the line in the workspace `README.md` that says how to open the site still holds.

## Acceptance criteria
- Opens with a double click on `index.html`, no server, in Chrome and Edge; also at phone width.
- From Home the same flow can be reached four ways: Domains, Flows, Endpoints and Screens; and from the screen it can be expanded in place down to the columns of a table.
- Every entity has its own URL; reloading the URL returns to the same view; browser back and forward work.
- Everything is collapsed by default; no initial view exceeds one screen in height with the seed data.
- No external dependencies and no network requests.
- `node tools/validate-docs.mjs` exits 0 with the seed data and fails with a clear message when a reference is broken (test it).
- Readable and plain: system font, good contrast, no animations.

## Out of scope
Loading the rest of the system; coverage tests against the code; publishing the site on the internet.

## Closing
Verify by opening the site in a browser (screenshots if a tool is available; otherwise describe what was checked). Commits: workspace, backend and frontend (`T-001: ...`). Update `PLAN.md` and `STATE.md`.
