# T-302 — Modes, language, profile data and the entry gates

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** backend · **Milestone:** H3 · **Requires:** T-301 helpful (shared identity surfaces), not blocking

## Goal
Make the account's mode and interface language real identity state, give the frontend its one
`my-data` read, enforce the display-name limit, wire the market-and-age gate into the two entries
that exist (create-game and session join), and let admin publish acceptance texts. P03§9, P19, P35
and P15§5 govern.

## Read first
- Site data: `identity.set-mode`, `identity.set-language`, `identity.read-profile`, the changed
  `identity_users` / `identity_accounts` / `identity.set-display-name`, the `my-data` flow, the
  changed `create-game` and `join-session` flows, `compliance.read-declaration`,
  `compliance.admin-list-texts` / `admin-publish-text`, and the new endpoints (`GET /v1/me`,
  `PUT /v1/identity/me/mode`, `PUT /v1/identity/me/language`, `GET/PUT /admin/v1/texts`).
- `DECISIONS.md` D-034, D-037, D-038, V-10; P03§9, P19 in full, P35§3,§5; P15§5.
- `playhoot/AGENTS.md`; `compliance/usecases/marketaccess` as built (D-016); `api/geolocation`.

## What to build
1. **Mode**: `mode` on `identity_accounts` (normal | teacher, data-trailed), carried by the access
   token; `SetMode` answers a fresh access token; guests refused. The retired `switch-mode` flow
   stays retired: no plan call at switch time (P15§5, D-034).
2. **Language**: `interface_language` on `identity_users`, set by accounts only; `read-contact`
   returns it so emails follow it (V-07 default only when empty).
3. **Profile reads**: `ReadProfile` (identity) and `ReadDeclaration` (compliance); the composer
   `my-data` flow behind `GET /v1/me` per its documented steps — identity, declaration when an
   account, free limits always; a missing piece is answered as missing, never an error.
4. **Display-name limit**: 3 per rolling 30 days counted from the existing change history (V-10);
   the refusal names when the next change is possible.
5. **Entry gates (D-038)**: `create-game` gains the `check-market-access` first step (function
   `create-games`; `declaration_required` outcome carries the function kind); the session-join
   admission (the `check-join` path behind the WS routes and join code) gains the `interactive-use`
   check with the approximate country for guests. The declaration endpoint already exists (T-103);
   nothing else changes in compliance's core.
6. **Admin texts**: `AdminListTexts` / `AdminPublishText` and `GET/PUT /admin/v1/texts` (admin
   level, no step-up — publishing a text is recorded, not destructive), per the site data.
7. Site data for everything built → `implemented`, corrected where building taught otherwise;
   validator at 0. `TestH1Walkthrough` stays green (it exercises compliance and the queue).

## Acceptance criteria
- `go build ./... && go vet ./... && go test ./...` green.
- Tests cover: mode switch and its token, guest refusal, language set and read at send time,
  my-data for anonymous-token/guest/account, name-change limit window, create-game refused with
  `declaration_required` then allowed after declaring, join blocked from a blocked market and
  admitted when the locator answers unknown, text publishing immutability and version bump.
- Validator at 0; commit and push.

## Out of scope
Frontend (T-304/T-305/T-306); deletion (T-303); teacher entitlements and plans (H6); student mode
(H8); publish/subscribe/teach gates (H4/H6/H8).

## Result

**Done (16-nov-2026).** Everything in "What to build" is implemented, with the site data moved to
`implemented` and corrected where building taught otherwise (D-040). `go build`, `go vet` and
`go test ./...` are green with a database (`TestH1Walkthrough` included); the documentation
validator reports 456 entities at 0.

**Mode.** `mode` on `identity_accounts` (edited into the original migration), with its changes in
the new append-only `identity_setting_changes` — the data-history standard asks for a history
table, not a trail on the row. `identity/usecases/setmode` answers a fresh access token carrying
the mode and no refresh token; guests are refused (`not_account`). The `mode` claim is on every
token now: refreshing and both sign-in completions read it in the query they already ran. The
retired `switch-mode` flow stays retired.

**Language.** `interface_language` on `identity_users`, written by `identity/usecases/setlanguage`
(accounts only, es/en/pt, changes kept in the same settings history) and returned by
`read-contact`, so an email is written in the language the account chose and falls back to V-07's
default only when it chose none.

**Profile reads.** `identity/usecases/readprofile` (listing methods through `signinmethods`, not a
second copy of its query) and `compliance/usecases/readdeclaration`; `composer/mydata` composes
them with `plan.get-user-limits` behind `GET /v1/me`. A piece that could not be read is answered
as missing (`declaration_known`, `limits_known`), never as a failure; a guest is never asked for a
declaration.

**Display-name limit.** 3 changes per rolling 30 days counted from
`identity_display_name_changes` (V-10); the refusal is 429 `change_limit_reached` with
`next_change_at`. Choosing the name already in force is not a change.

**Entry gates.** `orchestrator/marketgate` turns Compliance's decision into a declaration owed
(carrying the function kind) or a service restriction. `create-game` calls it as its first step
and the API answers 403 `declaration_required` with the function, or `market_restricted`. The
session-join admission calls it as a middleware on the three live routes **before** join-code and
owner routing, so a refusal never reveals whether the Session exists; the refusal travels on the
upgraded socket with the same two reasons. `api/geolocation` was unused: the edge now notes the
client address on every request and only the handlers that need a country ask the locator, which
locally always answers unknown — the gates are live and open in development.

**Admin texts.** `compliance/usecases/admintexts` and `GET/PUT /admin/v1/texts` at admin level,
new operation `MANAGE_TEXTS`, no step-up. Versions are counted per kind and language and are never
edited; the catalog lists every kind-language pair, missing ones included, so the creator sees what
P-23 still owes.

**New operations** (catalog and its test): `SET_OWN_MODE`, `SET_INTERFACE_LANGUAGE`,
`MANAGE_TEXTS`. New API group `api/me` holds `GET /v1/me`, `PUT /v1/identity/me/mode` and
`PUT /v1/identity/me/language`.

**The creator must recreate the local database**: the identity migrations were edited in place
(`identity_users.interface_language`, `identity_accounts.mode`, the new
`identity_setting_changes`). `playhoot_t301` is stale for this reason; the suite was run against a
database it created and dropped itself.

**Out of scope as planned**: the frontend (T-304/T-305/T-306), deletion and guest expiry (T-303),
teacher entitlements and student mode.
