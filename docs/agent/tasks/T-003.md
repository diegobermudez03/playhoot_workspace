# T-003 — Cleanup of both repos

**Tier:** C (Sonnet · medium) · **Size:** M · **Repos:** backend, frontend · **Milestone:** H0

## Goal
That only current documentation remains in the repos, so that no future session reads or follows the previous process. Decision D-004.

## Read first
- `docs/agent/METHOD.md` §2, §7, §8.
- `docs/agent/inventory/backend-entrypoints-infra.md` §6.5 and §7; `docs/agent/inventory/frontend.md` §8.
- `playhoot/AGENTS.md` and `playhoot_frontend/AGENTS.md` (already rewritten: do not change their meaning).

## What to do
**Backend (`playhoot/`)**
- Delete: `docs/ai/`, `docs/archive/`, `docs/work/`, `docs/projects/`, `plans/`, all `CURRENT_STATE.md`, `PROJECT_OVERVIEW.md`, `docs/engineering/ENGINEERING_RADAR.md`, and any `HUMAN_REVIEW.md`/`AI_CONTEXT.md` that exist.
- Keep: `docs/engineering/standards/` in full; `docs/engineering/LAUNCH_READINESS.md` (its content moves to the workspace's `docs/agent/CREATOR_TODO.md` if not already there; then it is deleted); the current ADRs (global and per-domain) moved to `docs/technical-decisions/` as a historical reference of why the runtime is the way it is; `ARCHITECTURE.md` only if, after removing the obsolete parts, something remains that is not in the documentation site: if not, delete it and let the site be the source.
- Domain READMEs (`play/README.md`, `orchestrator/README.md`, `game/…`): delete the outdated ones (inventory §11); the site replaces them.
- Remove `playhoot.exe` from version control (`git rm --cached`) and add `*.exe` to `.gitignore`.
- Delete the folders without code `community/`, `profile/`, `sessionhistory/` and the empty directories listed in the domain inventory §3.9.
- Adjust `comment_standard_test.go` only if some documentation path it watches ceases to exist.

**Frontend (`playhoot_frontend/`)**
- Delete: `docs/ai/`, `docs/work/`, `docs/projects/`, `docs/logic/` (Logic Mirror), `CURRENT_STATE.md`, `docs/Playhoot_Frontend_Architecture_Plan.docx`, `docs/engineering/ENGINEERING_RADAR.md`, `apps/mobile/`.
- Keep: `docs/engineering/standards/`, technical ADRs (move to `docs/technical-decisions/`), `docs/architecture/BACKEND_CONTRACT.md` (until the site replaces it in T-005), `docs/design/ASSETS.md` and the asset registry. `docs/design/DESIGN_SYSTEM.md` is kept, marked in its first line as "previous identity, redefined in H2".
- `ARCHITECTURE.md`: keep only the technical invariants that are still in force (game isolation, bridge, layers, URL navigation); remove references to the old process and the mobile app.

**Both**
- Search for broken references to what was deleted (`grep` for `docs/ai`, `KNOWLEDGE_MAP`, `OPERATING_MODEL`, `WORK-`, `HUMAN_REVIEW`, `AI_CONTEXT`, `CURRENT_STATE`, `docs/logic`) in files that are kept and fix or remove them.
- Do not touch product code except as indicated.

## Acceptance criteria
- Checks green: backend `go build ./... && go vet ./... && go test ./...`; frontend `npm run check`.
- `grep` for the above terms returns no results outside `docs/technical-decisions/`.
- Nothing deleted was the only source of a current technical rule: if one is found, it is moved to the corresponding standard or to the repo's `AGENTS.md` before deleting, and noted in the result.

## Result
Done 2026-11-15. Backend commit `bf1cb23`, frontend commit `a9e9ba5`.

**Backend:** deleted `docs/ai`, `docs/archive`, `docs/work`, `docs/projects`, `plans/`, `docs/product`, `docs/architecture` (SYSTEM_MAP and CROSS_DOMAIN_FLOWS described a state long gone), every `CURRENT_STATE.md`, `PROJECT_OVERVIEW.md`, `ENGINEERING_RADAR.md`, the READMEs of `game`, `identity`, `play`, `orchestrator`, the codeless `community/`, `profile/`, `sessionhistory/` and the empty `sessionlifecycle/internal/*` folders. `playhoot.exe` left version control and `*.exe` is ignored. ADRs moved to `docs/technical-decisions/{global,game,identity,play}/`. `ARCHITECTURE.md` kept but trimmed to the invariants in force (domain boundaries, public entity references, authorization split, intra-domain responsibility); its old "accepted boundaries / layout / open questions" parts were removed. `LAUNCH_READINESS.md` moved to `docs/agent/CREATOR_TODO.md` (items D-01 to D-16) and deleted. Kept: standards, `api`, `composer`, `discovery`, `monitoring`, `utils`, `deploy` READMEs, `game/docs` and `play/docs` (DATA_MODEL, FLOWS) until the site replaces them. `comment_standard_test.go` needed no change (it watches comment text, not paths); its pattern still names `WORK-NNNN`/`docs/work` on purpose, so the grep matches there.

**Frontend:** deleted `docs/ai`, `docs/work`, `docs/projects`, `docs/logic`, `docs/decisions` (ADRs moved to `docs/technical-decisions/`), `CURRENT_STATE.md`, the architecture plan DOCX, `ENGINEERING_RADAR.md`, `apps/mobile/`. `ARCHITECTURE.md` lost the plan, mobile and old-process references and keeps the 15 invariants. `DESIGN_SYSTEM.md` is marked as previous identity. Root and package READMEs no longer point to deleted files. `eslint.config.js` only lost a comment reference (its `@playhoot/mobile` forbidden-import group is untouched).

**Rules moved before deleting:** none were the only source. Standards that pointed to the retired standard-change process now point to `DECISIONS.md`; the placeholder rule in `code-comments.md` now points to the system documentation data instead of `CURRENT_STATE.md`.

**Checks:** backend `go build`, `go vet`, `go test` green (database tests skipped, as before); frontend `npm run check` green (53 files, 494 tests; 17 registered assets missing, expected); docs validator OK. The old-process grep returns nothing outside `docs/technical-decisions/` except the intentional pattern in `comment_standard_test.go`.

**Left for later:** the ADR texts keep their old internal paths (history, not edited). `game/docs` and `play/docs` and `docs/architecture/BACKEND_CONTRACT.md` are to be replaced by the site (T-005 for the contract).
