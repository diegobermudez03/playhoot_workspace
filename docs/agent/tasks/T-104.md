## Result
Done 2026-11-15 (Sonnet · medium). Backend commit `T-104: add the plan domain with configurable free limits`.
- New domain `plan`: table `plan_free_limit_configs` (append-only, seeded with P27§2: 3 games, 2 creations / 5 sessions per 30 days, 10 players, 1 room, 100 MB), operations `get-user-limits`, `read-free-limits`, `admin-set-free-limits`, endpoints `GET`/`PUT /admin/v1/free-limits`. New Identity operation `MANAGE_PLANS` (admin level).
- `GetUserLimits` is a pure read: everyone gets the config in force; empty or unknown users never error; a future effective date is not active until it arrives; lowering only changes what is read, nothing is removed. Not called by any flow yet (consuming limits is out of scope; the owning domains do it in their milestones).
- Design correction: `created_by` (bigint) became `created_by_user_uuid` (uuid, null for the seeded row), as in Compliance (D-016). Site data set to `implemented` for the table, three operations and two endpoints; the `plan` domain itself stays `planned` until H6. Validator OK (404 entities).
- Tests: pure validation bounds; DB tests for defaults of unknown users, future date not active, latest effective wins, history preserved on lowering, invalid inputs write nothing; handler tests. `go build`, `go vet`, `go test ./...` green with the database.
- The migration is new: it applies on top, no need to recreate the local database.
