# T-201 — Rendering and SEO base

**Tier:** B (Opus · medium) · **Size:** M · **Repos:** frontend · **Milestone:** H2 · **Requires:** nothing (first H2 build task)

## Goal
Move `apps/web` from a pure SPA to React Router framework mode so public routes are server-rendered or prerendered with per-route metadata, per D-019 and the route part of D-022. Everything the app does today keeps working.

## Read first
- `DECISIONS.md` D-019, D-022 (and D-006 for what must not change).
- `playhoot_frontend/AGENTS.md` (layers, package boundaries, i18n rules).
- Site data: screens `home`, `app-shell` (`playhoot_frontend/docs/system/screens-shell.js`) — this task builds the routing/rendering base they sit on, not the screens themselves.
- React Router v7 framework-mode docs (routes.ts, `ssr`, `prerender`, `meta`, hydration).

## What to build
1. Adopt framework mode in `apps/web` (react-router is already v7): route modules, `ssr: true`, root layout. The existing screens keep working as client-rendered routes; do not redesign them here.
2. Locale-prefixed public route group (`/:locale(es|en|pt)/…`) for the public pages that exist now (the current `/join` entry and sign-in) plus the future home; the bare path redirects by stored preference, else `Accept-Language`, else `en`. Authenticated/app routes stay unprefixed.
3. A per-route metadata convention: title, description, canonical, hreflang alternates (es/en/pt), Open Graph, and JSON-LD where the route declares it. Localized via the existing react-intl catalogs; no literal text (lint).
4. `robots.txt` and a per-locale sitemap for public routes.
5. `prerender` for public routes whose content is fixed at build time; SSR for the rest. Server code must not import feature state that assumes a browser (guard `window`/storage access).
6. Keep `npm run dev`, `build`, `preview` working; document the new serve shape (Node server output) in the repo README section the build touches.

## Acceptance criteria
- `npm run check` passes (PowerShell); dev server, build and preview run.
- `curl` of a public route returns HTML containing the rendered content and its meta/hreflang/JSON-LD without executing JS; each locale path renders in its language.
- Existing flows (join, lobby, play, creation workspace) still work in the browser after hydration.
- Site data: no screen changes here; if route paths of existing implemented screens change (locale prefix), update their `path` in `docs/system/` and keep the validator at 0.

## WCAG 2.2 AA checks (this task)
- The document has a correct `lang` attribute per locale, including after client navigation.
- Route changes move focus to the new page's heading or announce it (focus management in the root layout).
- No content flashes untranslated or unstyled on hydration.

## Out of scope
Home's real content (T-204), visual redesign (T-203), PWA (T-202).
