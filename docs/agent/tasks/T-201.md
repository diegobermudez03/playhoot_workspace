# T-201 — Rendering and SEO base

**Tier:** B (Opus · medium) · **Size:** M · **Repos:** frontend · **Milestone:** H2 · **Requires:** nothing (first H2 build task)

## Goal
Move `apps/web` from a pure SPA to React Router framework mode so public routes are server-rendered or prerendered with per-route metadata, per D-019 and the route part of D-022. Everything the app does today keeps working.

## Read first
- `DECISIONS.md` D-019, D-022 (and D-006 for what must not change).
- `playhoot_frontend/AGENTS.md` (layers, package boundaries, i18n rules).
- Site data: screens `home`, `app-shell` (`playhoot_frontend/docs/system/screens-shell.js`) — this task builds the routing/rendering base they sit on, not the screens themselves.
- React Router v7 framework-mode docs (routes.ts, `ssr`, `prerender`, `meta`, hydration).

## What to build
1. Adopt framework mode in `apps/web` (react-router is already v7): route modules, `ssr: true`, root layout. The existing screens keep working as client-rendered routes; do not redesign them here.
2. Locale-prefixed public route group (`/:locale(es|en|pt)/…`) for the public pages that exist now (the current `/join` entry and sign-in) plus the future home; the bare path redirects by stored preference, else `Accept-Language`, else `en`. Authenticated/app routes stay unprefixed.
3. A per-route metadata convention: title, description, canonical, hreflang alternates (es/en/pt), Open Graph, and JSON-LD where the route declares it. Localized via the existing react-intl catalogs; no literal text (lint).
4. `robots.txt` and a per-locale sitemap for public routes.
5. `prerender` for public routes whose content is fixed at build time; SSR for the rest. Server code must not import feature state that assumes a browser (guard `window`/storage access).
6. Keep `npm run dev`, `build`, `preview` working; document the new serve shape (Node server output) in the repo README section the build touches.

## Acceptance criteria
- `npm run check` passes (PowerShell); dev server, build and preview run.
- `curl` of a public route returns HTML containing the rendered content and its meta/hreflang/JSON-LD without executing JS; each locale path renders in its language.
- Existing flows (join, lobby, play, creation workspace) still work in the browser after hydration.
- Site data: no screen changes here; if route paths of existing implemented screens change (locale prefix), update their `path` in `docs/system/` and keep the validator at 0.

## WCAG 2.2 AA checks (this task)
- The document has a correct `lang` attribute per locale, including after client navigation.
- Route changes move focus to the new page's heading or announce it (focus management in the root layout).
- No content flashes untranslated or unstyled on hydration.

## Out of scope
Home's real content (T-204), visual redesign (T-203), PWA (T-202).

## Result

**Done 2026-11-15.** `apps/web` runs on React Router framework mode. `react-router.config.ts`
(`appDirectory: 'src'`, `ssr: true`) replaces the SPA entry: `index.html`, `main.tsx` and
`app/router.tsx` are gone, and `src/root.tsx` (the document, providers, focus on route change),
`src/routes.ts` (the route table) and `src/entry.client.tsx` take their place. The sign-in code is
still removed from the URL before any other module runs: `entry.client.tsx` imports
`captureSignIn` first.

**What renders where.** Public pages sit outside the app: `/es`, `/en`, `/pt` (home) render fully
on the server and are written out at build time; their `/join`, `/sign-in` and `/sign-in/guest`
are server-rendered documents whose content is taken over at hydration. Everything else — every
screen that needs the browser (the credential, storage, the device, live connections) — hangs off
one pathless `app/ClientLayout.tsx`, which renders nothing on the server and mounts the app as it
has always been after hydration. That is what "authenticated routes stay client-rendered" (D-019)
costs in practice, and it is why the existing screens did not have to change.

**Language in the path (D-022).** React Router v7 has no pattern constraint on a dynamic segment,
so the three language branches are declared one by one and `/es/…` can never swallow `/games`.
`i18n/localePaths.ts` owns the mapping (`pt-BR` → `/pt`), the cookie and the `Accept-Language`
reading; `i18n/LocaleContext.tsx` owns the language the page renders in and the change of it;
`i18n/useLocalePaths.ts` gives screens the public paths in the reader's language. The bare paths
(`/`, `/join`, `/sign-in`, `/sign-in/guest`) redirect. `I18nProvider` and `LanguagePicker` no
longer read platform state, and `AccountButton` and `SoundToggle` render nothing when there is no
app yet, so the shell renders on the server.

**Metadata.** `src/seo/meta.ts` builds title, description, canonical, hreflang alternates for the
three languages plus `x-default`, Open Graph and JSON-LD from the catalogs; every public route
uses it, so a page can never be indexed in one language under another language's address.
Sign-in pages are `noindex, follow`. `/robots.txt` and `/sitemap.xml` are routes, written out at
build time. A path no route answers now replies 404 instead of 200.

**Two new decisions.** D-024: the chosen language is mirrored in a `playhoot_locale` cookie,
because the server renders the first page of a visit and cannot read `localStorage`. D-025: the
deployable unit is `apps/web/server.js`, ours, not `react-router-serve` — that one logs every
request URL (a sign-in's one-time code travels in one) and answers `/es` with a redirect to
`/es/`, which is not the address the page's canonical link names.

**Verified.** `npm run check` green (506 tests, 12 new: locale resolution and public metadata).
Built with `PLAYHOOT_SITE_URL` set and served with `npm run start`: `/en` 200 with the content,
the metadata, the alternates and the JSON-LD in the HTML; `/es`, `/en` and `/pt` each render in
their own language with the right `lang`; `/` redirects by `Accept-Language` (`es-CO` → `/es`);
`/pt/sign-in` is server-rendered with Portuguese metadata; `robots.txt` and `sitemap.xml` answer.
Dev server: every route answers (`/join/{code}`, `/sessions/{uuid}/play`, `/design`,
`/dev/game-host`, `/sign-in/complete`).

**Not verified here.** Hydration and the existing flows in a real browser: this session has no
browser. The next session that runs the app should open `/en`, join a session and open a game
workspace before building on top. `apps/web/README.md` carries the new serve shape and its
requirements (`PLAYHOOT_SITE_URL` for the build and the server, no request logging with queries).

**Site data.** No new screens. The public screens that now carry the language were updated:
`enter-code` → `/{language}/join`, `sign-in` → `/{language}/sign-in`, `sign-in-guest` →
`/{language}/sign-in/guest`; `root-redirect` is now the bare public path that redirects; the
planned `home` and `auth-contextual` carry the language too, and `home` says that T-201 built its
rendering base and T-204 builds its content. Validator at 0 (417 entities).
