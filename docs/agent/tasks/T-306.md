# T-306 — Admin panels: markets and acceptance texts

**Tier:** C (Sonnet · medium) · **Size:** S · **Repos:** frontend · **Milestone:** H3 · **Requires:** T-302 (the texts endpoints)

## Goal
Add the two H3 panels to the admin area T-206 built: the market matrix over the H1 endpoints and
the acceptance-texts publisher over T-302's. Both follow the admin conventions exactly; nothing new
is invented here.

## Read first
- Site data: `admin-markets` and `admin-texts` (`playhoot_frontend/docs/system/screens-admin.js`),
  the endpoints they call (`GET/PUT /admin/v1/markets`, `GET/PUT /admin/v1/texts`,
  `GET /v1/compliance/texts/{kind}`).
- `DECISIONS.md` D-023, D-031 (the admin conventions), D-037; `STATE.md` note "A new admin panel
  adds…" (the checklist this task follows literally).
- `playhoot_frontend/AGENTS.md`; the existing admin panels in `apps/web/src/features/admin/` as the
  mold.

## What to build
1. **`/admin/markets`**: the matrix grouped by country (subdivision rows where they exist) and
   function — enabled, age, conditions note, actor, reason, effective date; tabs or filters for
   current / scheduled / history exactly as the endpoint answers them; the append form with
   effective date and reason; the `conditions_pending` 409 surfaced as "confirm the conditions are
   met and clear the note". Values rendered as the backend wrote them (D-031); no step-up (the
   operation is admin-level, not destructive).
2. **`/admin/texts`**: kinds × languages with version and publish date, missing pairs named
   plainly (P-23 points the creator here); the publish form with a preview of the text as served
   and the immutability warning; read/download of existing versions.
3. Feature state in `packages/features/admin`; routes inside the `AdminArea` layout; screen entries
   in `screens-admin.js` → `implemented`; titles and es/en/pt messages; navigation entries on the
   admin shell and its overview where it lists panels.

## Acceptance criteria
- `npm run check` (from PowerShell) green; validator at 0.
- In real admin mode against a live backend: read the seeded matrix, schedule a rule change with a
  reason and see it under scheduled, publish a text version and see `GET /v1/compliance/texts/…`
  serve it, re-publish a new version and see acceptances still point at the old one (the backend
  answers; the panel just shows it).

## WCAG 2.2 AA checks (this task)
- Tables with real headers and captions; the append/publish forms labeled with errors associated
  and announced; dialogs (if any) follow the admin `Dialog` pattern; keyboard-only operation of
  both panels; desktop-first single implementation still usable at 768 px (D-023).

## Out of scope
Free-limits and user/game admin panels (H10); moderation (H9); backend changes; step-up (not
required by these operations).
