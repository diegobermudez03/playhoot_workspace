# T-405 — Frontend: public Discovery

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** frontend · **Milestone:** H4 · **Requires:** T-403 (its endpoints), T-404 helpful (template mark on cards)

## Goal
Build the public face of the catalog: the Discovery page with its sections and search, the category
pages, the public game card, the home page's real catalog section, and the dynamic sitemap — all
server-rendered with their metadata, in the three languages (P14§1-2, D-019, D-051).

## Read first
- Site data: the screens `discovery`, `discovery-category`, `game-card-public`, the changed `home`,
  and the endpoints they call (`GET /v1/discovery*`).
- `DECISIONS.md` D-048, D-051, V-13; D-019/D-024/D-025 (how public routes render), D-029 (the
  honesty rule the home section keeps), D-032 (what verify:seo expects of a crawlable page).
- `playhoot_frontend/AGENTS.md`; `apps/web/src/routes.ts` and a built public route (the home) as
  the pattern; `scripts/verify/seo.mjs` for what must hold.

## What to build
1. **Discovery** (`/{language}/discovery`): sections without a query (popular, categories with
   samples, recently played only for a signed person — rendered client-side since identity is
   browser-only, D-028); results when the address carries a query; the whole search in the URL;
   tag helpers from the taxonomy; two implementations; server-rendered with title, description,
   canonical, hreflang and JSON-LD (ItemList). An empty catalog answers the honest D-029 wording.
2. **Category pages** (`/{language}/discovery/c/{slug}`): by popularity, paged, filters; a wrong
   slug is the real 404.
3. **The public card** (`/{language}/g/{gameUUID}`): everything the `game-card-public` site entry
   lists, including the not-available outcome; "start a session" through the sign-in gate; "create
   a game based on this" only with the template permission; the owner's way into the workspace.
4. **Home**: the curated kinds-of-game section becomes the real teaser (popular + categories) with
   its honest empty state; the join/create/teach accesses untouched.
5. **Sitemap and SEO** (D-051): a sitemap index — the build-time part plus a host-served
   `/sitemap-discovery.xml` fed by `GET /v1/discovery/sitemap` (the Express host serves it;
   no request logging, D-025); robots allows the new public routes; `verify:seo` learns the new
   pages (including one seeded public card in the three languages).
6. New messages in the three catalogs (parity test); `appMeta` titles for every new page; any new
   core component (a game card tile, a tag picker) into the `/design` gallery; the a11y screen
   lists gain the new pages.

## WCAG 2.2 AA checks (verify:a11y + keyboard pass)
- Discovery, a category page and a public card audited at both sizes; zero axe A/AA violations.
- The search form: visible labels, the tag any/all choice reachable and announced; results update
  announced (aria-live) without stealing focus; filters operable by keyboard.
- Card images carry alt text from the snapshot name; the statistics line is plain text, not only
  color; focus order on the card page reaches the main action first after the heading.
- No horizontal scroll at the five checked widths; the URL reproduces every view.

## Acceptance criteria
- `npm run check` green (PowerShell); `verify:seo` green against a production build with the new
  pages; `verify:a11y` green with the new lists; `verify:pwa` untouched and green.
- Site data (screens) → `implemented`; validator at 0; commit and push.
