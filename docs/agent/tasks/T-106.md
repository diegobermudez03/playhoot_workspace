# T-106 — Notifications and outbound email

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** backend · **Milestone:** H1 · **Requires:** T-101, T-105

## Goal
The new `notifications` domain: one logical entry per event, in-app plus email, Resend/SES behind ports with admin modes, suppressions and 30-day delivery records.

## Read first
- `playhoot/docs/system/notifications.js` in full (six tables, eight operations, the delivery lifecycle).
- Flows `deliver-notification` and `send-notification-email` in `flows.js`; `DECISIONS.md` D-010.
- `docs/definitivos/md/post_31_correo_resend_ses_y_canales_de_avisos.md` in full (the §4 matrix becomes the type constants); P29 and P14§4-6 via SPEC_MAP §17.

## Deliverables
1. The six tables and eight operations as documented; notification type constants carrying the P31§4 matrix (channels, necessary flag, student no-email rule).
2. The orchestrator handler for `notify` tasks (flow `deliver-notification`) and the email task processor (flow `send-notification-email`: admit → send → settle, with email spend events fed back through the queue).
3. Both providers behind one outbound port. Delivery 1 ships **simulated local implementations** with the real contract: Resend-sim enforcing 100/day-3,000/month joint quotas with clear quota rejections, SES-sim always-accept with per-send cost, plus injectable failures and uncertain responses. The real HTTP clients are delivery 2; no throwaway code in the port surface.
4. Rendering: minimal content, user's language (es/en/pt), unsubscribe link for optional types, no tracking. Delivery rows expire at 30 days via a periodic task.
5. User endpoints (list, mark read, preferences), unsubscribe, provider webhooks, admin status and mode endpoints.
6. Docs to `implemented`.

## Acceptance criteria
- Repo checks green. Tests at least: idempotent acceptance (same source+key once); matrix decides channels and preferences only trim optional ones; quota exhaustion switches to SES only on clear rejection; accepted-by-one never resent; uncertain response not immediately retried on the other; suppression honored on both and via unsubscribe; email never marks read; delivery records carry no bodies.
- Validator at 0.

## Out of scope
Composer join of entries with entities and destination URLs (needs the frontend URL builder — H2+; the gap stays in `notification-list`'s `touches`). Inbound support email (H9). Emails emitted by other domains' events (each milestone wires its own notify tasks).
