# T-200 — H2 design: frontend base and visual identity

**Tier:** A (Fable · high) · **Size:** L · **Repos:** workspace, frontend · **Milestone:** H2 · **Requires:** H1 closed

## Goal
Design everything H2 builds: rendering for SEO and the PWA, the visual direction (C-03), the design system, the app structure (fixed bar, mode switch, language), contextual authentication, the admin web base and AA accessibility as a criterion. Write the design as `planned` documentation data (screens and their calls) and write the implementation tasks T-201…

## Read first
- `docs/agent/SPEC_MAP.md` §1, §19, §20, §23 and the H2 row in `PLAN.md`; `DECISIONS.md` C-03.
- Patches in full: P14, P24 (§3-5), P01§5; base document sections on frontend/UI and personality (`docs/definitivos/md/`).
- `playhoot_frontend/AGENTS.md` and its site data (`playhoot_frontend/docs/system/`), plus `GAPS.md` "Frontend".
- The visual references at the workspace root: `gatita_lottie.json`, `lottie.json`.

## Deliverables
1. **C-03:** 2–3 visual directions rendered on real screens (home/Discovery entry, lobby, teacher dashboard), with one recommended. Record the question's state in `DECISIONS.md`. The creator picks, or says "you decide". If the answer is pending, the design system tasks wait and the structure and accessibility tasks go on.
2. Screens in `planned` for the H2 scope: shell (fixed top bar, mode switch, language), public entry, contextual sign-in, admin web base (sign-in with second factor, navigation, queues/DLQ, budget status and email mode as first panels over the H1 endpoints), with the calls each screen makes.
3. D-NN decisions for rendering/SEO, PWA approach, design tokens and the i18n structure (es/en/pt).
4. Task briefs T-201… and the H2 board in `PLAN.md`.

## Acceptance criteria
- `node tools/validate-docs.mjs` at 0.
- Each implementation task is self-contained: an Opus/Sonnet session can build it from the brief plus the site data.
- Every implementation task lists WCAG 2.2 AA checks for the screens it builds.

## Out of scope
App code (the C-03 renders are design material, kept out of the app's source). Domain screens of later milestones (games, sessions, classroom, plans).
