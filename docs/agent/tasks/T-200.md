# T-200 — H2 design: frontend base and visual identity

**Tier:** A (Fable · high) · **Size:** L · **Repos:** workspace, frontend · **Milestone:** H2 · **Requires:** H1 closed

## Goal
Design everything H2 builds: rendering for SEO and the PWA, the visual direction (C-03), the design system, the app structure (fixed bar, mode switch, language), contextual authentication, the admin web base and AA accessibility as a criterion. Write the design as `planned` documentation data (screens and their calls) and write the implementation tasks T-201…

## Read first
- `docs/agent/SPEC_MAP.md` §1, §19, §20, §23 and the H2 row in `PLAN.md`; `DECISIONS.md` C-03.
- Patches in full: P14, P24 (§3-5), P01§5; base document sections on frontend/UI and personality (`docs/definitivos/md/`).
- `playhoot_frontend/AGENTS.md` and its site data (`playhoot_frontend/docs/system/`), plus `GAPS.md` "Frontend".
- The visual references at the workspace root: `gatita_lottie.json`, `lottie.json`.

## Deliverables
1. **C-03:** 2–3 visual directions rendered on real screens (home/Discovery entry, lobby, teacher dashboard), with one recommended. Record the question's state in `DECISIONS.md`. The creator picks, or says "you decide". If the answer is pending, the design system tasks wait and the structure and accessibility tasks go on.
2. Screens in `planned` for the H2 scope: shell (fixed top bar, mode switch, language), public entry, contextual sign-in, admin web base (sign-in with second factor, navigation, queues/DLQ, budget status and email mode as first panels over the H1 endpoints), with the calls each screen makes.
3. D-NN decisions for rendering/SEO, PWA approach, design tokens and the i18n structure (es/en/pt).
4. Task briefs T-201… and the H2 board in `PLAN.md`.

## Acceptance criteria
- `node tools/validate-docs.mjs` at 0.
- Each implementation task is self-contained: an Opus/Sonnet session can build it from the brief plus the site data.
- Every implementation task lists WCAG 2.2 AA checks for the screens it builds.

## Out of scope
App code (the C-03 renders are design material, kept out of the app's source). Domain screens of later milestones (games, sessions, classroom, plans).

## Result
Done 2026-11-15, one session (Fable · high).

1. **C-03 prepared and asked.** Three directions rendered on the three real screens (home/public entry, host lobby, teacher dashboard) with identical content so only identity differs: `docs/agent/designs/c03/index.html` (A — Ink & Sticker, **recommended**; B — Warm Paper; C — Soft Clay), each with live hover/press/idle motion, palette, type and an animated placeholder cat per the gatita references. Recorded in `DECISIONS.md` as `asked`, with the comparison table and the answer format. Design material only; nothing entered the app source.
2. **Decisions D-019…D-023 + V-08:** React Router framework mode with SSR/prerender, per-route metadata and locale-prefixed public paths (D-019); PWA with manifest + service worker, no push ever, non-intrusive install offer (D-020, V-08); three-tier CSS token system so structure tasks can proceed on neutral values while C-03 is pending (D-021); i18n with es/en/pt public paths + remembered preference (D-022); admin as a `/admin` area of the same app, single responsive implementation, in-memory 15-min token, inline step-up (D-023).
3. **Planned screens loaded** (validator at 0, 417 entities): `screens-shell.js` (`app-shell`, `home`, `auth-contextual`) and `screens-admin.js` (`admin-sign-in`, `admin-second-factor`, `admin-home`, `admin-queues`, `admin-budget`, `admin-email`), every action mapped to the implemented H1/identity endpoints.
4. **Tasks T-201…T-207 written** and the H2 board added to `PLAN.md`: T-201 rendering/SEO → T-202 PWA → T-204 shell+home → T-205 contextual auth → T-206 admin base → T-207 close, with T-203 (design system) blocked on C-03 and slotted in when answered. Every implementation brief lists its WCAG 2.2 AA checks.

Scope note: the H2 deliverable "screens in planned for the H2 scope" deliberately excludes a dedicated notifications page (the shell gets a plain panel over the existing endpoints; the full page belongs to the milestone that owns its flows) and admin panels whose endpoints exist but whose UX belongs elsewhere (free limits, markets → H10/H3).
