# T-407 — Admin panels: reviews, taxonomy, featured templates, game block

**Tier:** C (Sonnet · medium) · **Size:** M · **Repos:** frontend · **Milestone:** H4 · **Requires:** T-402, T-403, T-404 (their admin endpoints)

## Goal
The four H4 admin panels in the existing admin shell, following the T-206 checklist: the
publication review queue with its decide actions, categories and tags, the featured-template
selection, and finding/blocking a game. P04§4, P13§5-6 and the site data govern.

## Read first
- Site data: the screens `admin-reviews`, `admin-taxonomy`, `admin-featured-templates`,
  `admin-games` and the `/admin/v1/…` endpoints they call.
- `playhoot_frontend/AGENTS.md` (the admin rules: one responsive implementation, desktop-first, the
  admin HTTP client, backend values never closed lists); D-023/D-031; the T-306 panels
  (`admin-markets`, `admin-texts`) as the closest pattern; D-044 (dialog focus).
- No step-up on these actions (they are recorded and reversible); the admin token alone gates them.

## What to build
1. **Reviews** (`/admin/reviews`, detail at `/admin/reviews/{uuid}`): the pending queue oldest
   first with age and count; the detail showing the exact submitted combination (snapshot fields,
   cover and screenshots, version facts, the academic claim, the private-content declaration, the
   game's current state); approve, deny-with-required-note, and the moot/cancel outcome; a block
   shortcut into the admin-games action.
2. **Taxonomy** (`/admin/taxonomy`): categories (ordered) and tags, three names each, create /
   rename / reorder / retire with reasons, history beside each entry, retired shown as retired.
3. **Featured templates** (`/admin/featured-templates`): the ordered selection, lapsed entries
   shown hidden, add by identifier / reorder / remove with reasons.
4. **Games** (`/admin/games?q=`): search by identifier, name or owner; one game's state; block and
   unblock confirmed with the reason kind, worded as what the owner will see.
5. Feature state in `packages/features/admin`; screens in `apps/web/src/features/admin/`; messages
   in the three catalogs; `appMeta` titles; the a11y admin list (run with `--totp-secret` and
   `--account`) gains the four panels.

## WCAG 2.2 AA checks (verify:a11y admin pass + keyboard)
- Zero axe A/AA violations on the four panels; tables with real headers; every action reachable by
  keyboard; confirm dialogs focus their safe action (D-044); deny's note field labelled and its
  requirement announced; nothing relies on color alone for states.

## Acceptance criteria
- `npm run check` green (PowerShell); `verify:a11y` green including the admin pass.
- Site data → `implemented`; validator at 0; commit and push.

## Out of scope
The complete admin games panel with history and relationships (H10). Appeals, measures beyond the
game block, classification (H9). Any backend change (if an endpoint answer is missing something,
record it in `GAPS.md` and stop that part).
