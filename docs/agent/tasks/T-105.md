# T-105 — Budget core: metering, admission and the restriction ladder

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** backend · **Milestone:** H1 · **Requires:** T-101, T-102

## Goal
The new `budget` domain, minimal core: rates, caps, spend ingestion, reservation-based admission, and the automatic restriction ladder with manual-only shutdown recovery. This is risk logic: implement exactly what the design says; deviations go back to a design task.

## Read first
- `playhoot/docs/system/budget.js` in full (five tables, eight operations, the `RESTRICTION_LADDER` lifecycle).
- Flows in `flows.js`: `spending-restriction`, `adjust-cost-controls`, `emergency-cutoff`, `reopen-spending`, `ingest-spend-events`.
- `DECISIONS.md` D-010, D-012, V-04; `docs/definitivos/md/post_32_control_de_costos_y_suspension_de_emergencia.md` in full.

## Deliverables
1. The five tables; caps and rates seeded with V-04 defaults and a starter rate set (ses-outbound 0.0001 USD/email; storage and compute placeholder rates flagged as estimates).
2. Operations `record-spend`, `admit-work`, `settle-work`, `evaluate-ladder` (periodic task via txqueue + run after ingestion), `admin-set-controls`, `admin-cutoff`, `reopen`, `status`.
3. The orchestrator handler for `spend-event` tasks (flow `ingest-spend-events`) and the four admin flows/endpoints, step-up proofs consumed via T-102's helper (`orchestrator/stepup`, see D-015; the admin endpoints take the proof from `POST /v1/identity/totp/verify` with purpose `step_up`).
4. Admission refusals worded as service restrictions; expired reservations swept by a periodic task.
5. Docs to `implemented` (including the flows).

## Acceptance criteria
- Repo checks green. Tests must cover at least: idempotent ingestion; missing rate flags and blocks the category; admission across hour/day/month windows counting reservations and margin; concurrent admissions not over-spending a cap (DB-level test); ladder escalation, automatic de-escalation, shutdown sticking across "restart" (new process reads the same state); reopen only from shutdown, gradual, step-up required; cutoff idempotent.
- Validator at 0.

## Out of scope
Reserves, cash, surplus split, money panel (H6). Deployment-level controls (P32§8, launch). Callers adopting `admit-work` beyond email (each consumer's milestone).
