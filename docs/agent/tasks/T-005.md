# T-005 — Document the existing frontend

**Tier:** C (Sonnet · medium) · **Size:** M · **Repos:** frontend · **Milestone:** H0 · **Requires:** T-001, T-004

## Goal
Load into `playhoot_frontend/docs/system/` the current screens, their navigation and the calls they make, linked to the endpoints that T-004 left documented, in state `implemented`.

## Read first
- `docs/agent/designs/system-docs.md` §3 (`screen` entity).
- `docs/agent/inventory/frontend.md` §2, §3 and §7. Verify against `apps/web/src/app/router.tsx` and `packages/communication`.

## What to load
- The 15 production routes as screens (not the development-only ones), including the creation workspace sections as child screens or actions.
- Per screen: route, access, what it shows, actions with the endpoint they call and where they navigate, and whether it has horizontal/vertical variants.
- WebSocket connections as calls of the game and host screens.

## Acceptance criteria
- Validator at 0: every `calls` points to an endpoint that exists in the backend data.
- From any screen one can expand down to the backend flow it triggers.
- When finished, delete `docs/architecture/BACKEND_CONTRACT.md` if all its current content is covered by the site; if not, note what is missing.

## Result

Loaded 23 screens into `playhoot_frontend/docs/system/` as `implemented`, across three new/updated data files:
- `screens-identity.js`: root redirect, enter-code, sign-in, guest sign-in, sign-in-complete, not-found.
- `screens-sessions.js`: new-session and host-lobby (now with real actions), plus the two Join Session URLs (`join-by-code`, `session-play`), including their WebSocket connections as calls.
- `screens-games.js`: my-games, create-game, the game workspace and each of its 9 sections as its own screen (linked from the workspace's default screen by `navigatesTo`), connect-ai and the connected-AIs screen.

All `calls` resolve to the backend endpoints T-004 loaded; the validator passes at 0 errors (`node tools/validate-docs.mjs`: 322 entities, 23 screens). Access per screen was verified against `RequireOperation` in the route components, not inferred: `connect-ai` and `ai-connections` both gate on `EDIT_GAME` (account), correcting the "[inferred]" note in `docs/agent/inventory/frontend.md`.

`docs/architecture/BACKEND_CONTRACT.md` is **kept**, not deleted: it documents the wire-level contract (request/response JSON shapes, HTTP error codes, WebSocket message types and close codes, rate limits, seed game data) that the system documentation site deliberately excludes by design (`docs/agent/designs/system-docs.md` §1, §7: "no DTOs, signatures" nor long text). The site now covers everything that file said about which screen calls which endpoint and what each endpoint invokes; it does not and should not replace the protocol-level reference.

Frontend `npm run check` passes (typecheck, lint, format, 53 files / 494 tests; the asset-registry check still reports its 17 pre-existing missing files, unrelated to this task).
