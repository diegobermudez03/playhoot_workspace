# T-404 — Templates and the game quotas

**Tier:** B (Opus · medium) · **Size:** M · **Repos:** backend · **Milestone:** H4 · **Requires:** T-403

## Goal
Make the template permission real — the recorded grant, the provenance and credits chain, the
featured selection, disabling without destroying — and wire the plan's holding and creation
capacities into game creation, template copies included. P05, P12§14, P27 and D-047/D-049 govern.

## Read first
- Site data: `game.game_template_grants`, `game_provenances`, `game_featured_templates`, the
  operations `game.manage-template`, `record-provenance`, `admin-featured-templates`, the changed
  `game.find-template` and `game.game-lifecycle` (limits, provenance), the flows `enable-template`,
  the changed `create-game` (limits step, template branch), `my-games`, the changed `edit-draft`
  (provenance on template application), and the endpoints `/v1/games/{g}/template*`,
  `/admin/v1/featured-templates`, the changed `GET /v1/games`.
- `DECISIONS.md` D-047, D-049; P05 in full; P12§14, P27§2.
- D-016/D-037 (compliance texts as built: the `template-permission` kind is one of them; seed a
  draft outside production like the others and extend `CREATOR_TODO.md` P-23 — the creator writes
  the real text).

## What to build
1. **The grant** (`manage-template` + `enable-template` flow): market gate (`publish-games`), the
   current `template-permission` text read at its exact version, the asset-rights confirmation,
   the append-only grant rows; disable stops new copies only (P05§4). Endpoints per site data.
   `find-template` reads grants + offered publication; the two dropped booleans go from every
   caller (templates browse endpoints, MCP tools).
2. **Provenance**: `game-lifecycle` writes the provenance row on a template creation (source game,
   version, name snapshot, permission version); `record-provenance` covers `ApplyTemplate` through
   the changed `edit-draft` flow; the public card's credits read them (T-403's read already does).
3. **Featured**: the table, `admin-featured-templates`, its endpoints; `GET /v1/templates`
   (featured browse) reads the selection — only live grants with an offering show.
4. **Quotas** (D-049): `create-game` gains the `plan.get-user-limits` step; `game-lifecycle` applies
   the stricter of received and own counts (live games held; `game_create_requests` in the rolling
   window) with refusals `game_limit_reached` / `creation_limit_reached`; a template copy consumes a
   creation (P12§14). `GET /v1/games` becomes the composed `my-games` read (list + filters +
   capacities). Analytics events `template-enabled`, `template-copied`.
5. New identity operations in the catalog and its test. Migrations edited in place. Site data →
   `implemented`; validator at 0.

## Acceptance criteria
- Backend checks green, walkthroughs included.
- Tests cover: enabling without an offering refused; the grant recording the exact text version;
  a copy from a disabled template refused while an existing derivation survives; provenance written
  on copy and on template application; combining two templates keeping both rows; the featured list
  hiding a lapsed grant; creation refused at the holding and at the window limits, free defaults
  applying; a copy counting as a creation; my-games answering counts and capacities.
- Validator at 0; commit and push. Say whether the creator must recreate the local database, and
  add the template-permission text to `CREATOR_TODO.md` P-23.
