# T-203 — Design system from the chosen direction

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** frontend · **Milestone:** H2 · **Requires:** **C-03 answered** (check `DECISIONS.md`); T-201 useful but not required

> **Blocked until C-03 is answered.** If it is still `asked`, do not start this task; pick the next unblocked H2 task instead.

## Goal
Turn the visual direction the creator picked into the design system: token files per D-021 and the core component set, replacing the rejected "game night / owl" identity. Everything new in H2+ is built from these pieces.

## Read first
- `DECISIONS.md` C-03 (the answer and any adjustments), D-021, D-006.
- The chosen direction's render: `docs/agent/designs/c03/direction-<X>.html` — it is the identity contract: palette, type, surfaces, shadows, radii, motion feel, mascot treatment. The other two renders show what was rejected.
- `SPEC_MAP.md` §23 and P24§3-5 in full (`docs/definitivos/md/post_24_…`): vector-first assets, reusable motion components, reduced motion.
- `playhoot_frontend/AGENTS.md` (CSS Modules + tokens only; assets registry; i18n).

## What to build
1. Token files (CSS custom properties) in the three tiers of D-021: primitives from the chosen direction, semantic roles, component tokens where needed. Delete or quarantine the old identity's tokens so nothing new can use them.
2. Fonts: the direction's OFL families self-hosted via @fontsource; remove unused families.
3. Core components (presentation layer, shared by horizontal and vertical implementations): button (variants, sizes, press feedback), input + field (label, hint, error), select, code input (join/TOTP style), card, dialog, toast/status area, tag/chip, avatar, pill, tabs/mode-switch control, skeleton/loading, empty state, page heading. Each with focus-visible styling, disabled and busy states, and motion per tokens honoring `prefers-reduced-motion`.
4. The mascot slot: an SVG/Lottie-ready component with the placeholder cat registered as a pending asset (the creator sources or approves the final mascot; the direction render's inline SVG is the placeholder).
5. A plain component gallery route (dev-only or unlisted) showing every component in both orientations — this is the review surface for the creator and later tasks.
6. Restyle the existing implemented screens only as far as swapping tokens/fonts requires so the app stays coherent; their redesign belongs to their own milestones (D-006).

## Acceptance criteria
- `npm run check` passes; no component or screen uses raw colors, durations or shadows (lint already enforces tokens).
- The gallery shows every core component; visual spot-check matches the chosen render's identity.
- Old identity tokens/assets are no longer importable.

## WCAG 2.2 AA checks (this task)
- Every text/background pair in the semantic tokens ≥ 4.5:1 (normal) / 3:1 (large); UI component boundaries ≥ 3:1. Record the measured pairs in the Result.
- Focus visible on every interactive component, not obscured (WCAG 2.2 2.4.11), ≥ 3:1 against adjacent colors.
- Pointer targets ≥ 24×24 CSS px (2.5.8); components usable by keyboard alone; dialogs trap and restore focus correctly.
- All motion disabled or reduced under `prefers-reduced-motion`.

## Out of scope
Screen redesigns beyond token swaps; game-side SDK visual components (H7, P24§3); dark mode (none in phase 1).
