# T-203 — Design system from the chosen direction

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** frontend · **Milestone:** H2 · **Requires:** C-03 (answered 2026-11-15); T-201 useful but not required

> **Unblocked.** The creator chose **A — Ink & Sticker**, with no adjustments (C-03, closed at T-202). Build the system from `docs/agent/designs/c03/direction-a.html`.

## Goal
Turn the visual direction the creator picked into the design system: token files per D-021 and the core component set, replacing the rejected "game night / owl" identity. Everything new in H2+ is built from these pieces.

## Read first
- `DECISIONS.md` C-03 (the answer and any adjustments), D-021, D-006.
- The chosen direction's render: `docs/agent/designs/c03/direction-a.html` — it is the identity contract: palette, type, surfaces, shadows, radii, motion feel, mascot treatment. The other two renders show what was rejected.
- `SPEC_MAP.md` §23 and P24§3-5 in full (`docs/definitivos/md/post_24_…`): vector-first assets, reusable motion components, reduced motion.
- `playhoot_frontend/AGENTS.md` (CSS Modules + tokens only; assets registry; i18n).

## What to build
1. Token files (CSS custom properties) in the three tiers of D-021: primitives from the chosen direction, semantic roles, component tokens where needed. Delete or quarantine the old identity's tokens so nothing new can use them.
2. Fonts: the direction's OFL families self-hosted via @fontsource; remove unused families.
3. Core components (presentation layer, shared by horizontal and vertical implementations): button (variants, sizes, press feedback), input + field (label, hint, error), select, code input (join/TOTP style), card, dialog, toast/status area, tag/chip, avatar, pill, tabs/mode-switch control, skeleton/loading, empty state, page heading. Each with focus-visible styling, disabled and busy states, and motion per tokens honoring `prefers-reduced-motion`.
4. The mascot slot: an SVG/Lottie-ready component with the placeholder cat registered as a pending asset (the creator sources or approves the final mascot; the direction render's inline SVG is the placeholder).
5. A plain component gallery route (dev-only or unlisted) showing every component in both orientations — this is the review surface for the creator and later tasks.
6. Restyle the existing implemented screens only as far as swapping tokens/fonts requires so the app stays coherent; their redesign belongs to their own milestones (D-006).

## Acceptance criteria
- `npm run check` passes; no component or screen uses raw colors, durations or shadows (lint already enforces tokens).
- The gallery shows every core component; visual spot-check matches the chosen render's identity.
- Old identity tokens/assets are no longer importable.

## WCAG 2.2 AA checks (this task)
- Every text/background pair in the semantic tokens ≥ 4.5:1 (normal) / 3:1 (large); UI component boundaries ≥ 3:1. Record the measured pairs in the Result.
- Focus visible on every interactive component, not obscured (WCAG 2.2 2.4.11), ≥ 3:1 against adjacent colors.
- Pointer targets ≥ 24×24 CSS px (2.5.8); components usable by keyboard alone; dialogs trap and restore focus correctly.
- All motion disabled or reduced under `prefers-reduced-motion`.

## Out of scope
Screen redesigns beyond token swaps; game-side SDK visual components (H7, P24§3); dark mode (none in phase 1).

## Result

**Done 2026-11-15** (Opus · medium, as asked). The chosen direction is now the
design system: `playhoot_frontend/apps/web/src/ui/`. Nothing of the retired
"game night" identity is left in the code.

### Tokens (D-021, three tiers)

- `ui/tokens/primitives.css` — direction A's raw values: the paper scale
  (`#e9e2d4` board → `#ffffff` card), the ink scale, the eight accent fills,
  type, the 4 px space scale, radii, outline widths, the hard shadow offsets
  (2/4/6 px, no blur), motion durations and easings, the two tilts.
- `ui/tokens/semantic.css` — the roles components use: surfaces, ink, outline,
  focus, scrim, primary/accent/highlight/info/success/danger, shadows, the eight
  player colours, the mascot's skin, `--target-min` and the control heights.
- `ui/tokens.css` — imports both and holds the base element styles, the single
  focus rule and the reduced-motion collapse.
- Component tokens are tier 3, declared at the top of each module (`--btn-bg`,
  `--btn-offset`, …).
- Every `--night-*`, `--owl-*`, `--color-bg*`, `--color-border*`, `--shadow-card`
  and `--edge` is gone; the ten screens that used them were re-tokenised in the
  same pass (D-006: token swap only, no redesign).

### Fonts

Fredoka (display) and Nunito (body), already self-hosted via
`@fontsource-variable`, are kept — they are the direction's own families. Body
weight raised to 600 and labels to 800: a light weight looks washed out on warm
paper. `@fontsource/roboto` stays, loaded by the Google sign-in button alone,
because Google's branding guidelines require their type on it.

### Core components

New: `Field`, `Select`, `Dialog`, `Status` / `StatusArea` / `ToastStack`,
`Tag` / `Pill`, `ModeSwitch`, `Skeleton`, `EmptyState`, `PageHeading`, `Mascot`.
Rebuilt on the new skin: `Button` (one more variant and size), `TextField` (now
on `Field`), `Card` (tones and `tilted`), `CodeInput`, `CodeTiles`, `Avatar`
(one more size), `Logo`, `Confetti`, `AppShell`. Deleted: `Owl`, `Starfield`.

`Dialog` is the native `<dialog>`, so the focus trap, the restore on close and
Escape are the browser's, not ours. `ModeSwitch` is a radio group rather than
tabs, because it reveals nothing. Tabs that swap panels will arrive with the
first screen that needs them — nothing in H2 does.

### The mascot slot

`Mascot` draws its character from code in separable parts (head, eyes, tail,
bounce), which is what P24§3 prefers and what lets the character be replaced
without touching a screen. It carries the direction render's placeholder cat;
the final one is the new `mascot.primary`, a pending asset
(`CREATOR_TODO.md` P-15). Moods and entrances match the old owl's API, so the
thirteen call sites were a rename.

### Gallery

`/design` (development only) was rewritten into the review surface the task
asked for: every core component in its states, each set shown in both
orientations, then the implemented screens with fake state. The rule that a
later task adds its new core component here is in `AGENTS.md` and
`DESIGN_SYSTEM.md`.

### Measured contrast (WCAG 2.2 AA, sRGB)

Text pairs — ink `#23201c` on board 12.58 · on paper 15.05 · on sunken 13.92 ·
on card 16.22. Muted `#5c564d` on board 5.63 · paper 6.74 · card 7.26. Subtle
`#6b6458` on board 4.54 · paper 5.43 · card 5.85 (chosen so it passes on the
*darkest* surface). Danger text `#b3261e` on paper 6.07 · board 5.07. Success
text `#0a6355` on paper 6.66 · board 5.56.

Ink on every fill — coral 4.85 · marigold 10.21 · teal 7.39 · lilac 8.96 ·
sky 10.50 · rose 8.19 · lime 11.40 · tangerine 8.08. All ≥ 4.5 for normal text.

Component boundaries (needs 3:1) — carried by the ink outline, not the fill:
ink is ≥ 4.85 against any fill and ≥ 12.58 against any surface. This is why the
accent fills could stay as saturated as the render wanted; a fill alone (e.g.
marigold on paper, 1.48) never has to do that job.

### Verified in a real browser

Chrome over the DevTools protocol against the dev server:

- `/design` and `/en` render and hydrate in the new identity; console clean
  apart from a known formatjs pre-compilation warning. Screenshots reviewed.
- **Pointer targets (2.5.8):** 105 interactive elements on `/design`, none
  under 24 × 24 px.
- **Focus (1.4.11, 2.4.11):** tabbed through 70 elements with real key events;
  every one matched `:focus-visible` with a ≥ 2 px opaque outline.
- Reduced motion is collapsed globally in `tokens.css`; `Confetti` is removed
  outright under it, since a burst cannot usefully be slowed.

Not exercised: joining a session and opening a game workspace against a live
backend (carried over from T-201; it needs the backend running, which this task
did not need). The join and play screens were reviewed in the gallery with fake
state.

### One thing the brief got wrong, and what was done about it

The acceptance criteria said "lint already enforces tokens". **It does not** —
ESLint never read CSS in this repository, so the rule in `AGENTS.md` was
unenforced. Added `scripts/check-styles.mjs` (`npm run styles`, now part of
`npm run check`): it fails on a raw colour, a raw duration or a shadow with a
blur radius in any stylesheet outside the token files. It found seven real
violations on its first run — four pre-existing animation durations in
`HostScreen`, `SessionScreen`, `PlayScreen` and `Button` — all now tokenised
(`--duration-loop`, `--duration-pulse`, `--duration-idle`). One documented
exception: the Google sign-in button. D-027 records this.

### Also changed, and why

The favicon and the four placeholder app icons were redrawn from the new mark
(a marigold sticker with the ink play triangle). `STATE.md` said T-203 would not
touch the icons, but they were the night square with the owl's amber eyes:
leaving them would have shipped the retired identity in the browser tab and on
the home screen, against the criterion that old identity assets are no longer
reachable. They are still placeholders and **P-14 still stands** — the creator's
real art drops at the same paths with no code change. The PWA theme colour,
`site.webmanifest` and the offline page were moved to paper and ink for the
same reason.
