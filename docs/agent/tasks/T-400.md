# T-400 — H4 design: games, versions, publication and Discovery

**Tier:** A (Fable · high) · **Size:** L · **Repos:** workspace, backend, frontend · **Milestone:** H4 · **Requires:** H1, H2 and H3 closed

## Goal
Design everything H4 builds, and only design it: the game as a product with its card, the split of
versions out of `play/session` into `play/versions` with the four version conditions that must not
be confused, the publication request and its review (the review core of `moderation`), unpublish,
delete and administrative block as three different things, templates with permission and
provenance, categories and tags, public Discovery with search and the public card, "my games", and
the game and creation quotas. Write the design as `planned` documentation data — domains,
operations, flows, endpoints and screens with their calls — and write the implementation tasks
T-401… with the H4 board in `PLAN.md`. Write no application code.

Same shape of task as T-200 and T-300; read T-300's Result for what "design as site data" meant
for a milestone that touched both repositories.

## What is known to be missing (from `GAPS.md`, not a complete list)
- **Versions inside `play/session`**: split into `play/versions`; the four conditions (in editing,
  ready and chosen for new sessions, approved for Discovery, pinned in a session) as distinct state.
- **Publication is automatic today**: request, admin review of version + card + assets together,
  and the previously approved combination staying public while an update is reviewed.
- **Version history, returning to a previous one, unpublish, delete**: none exist; single-game
  deletion feeds the same cleanup pattern as account deletion (D-036).
- **Templates**: the copy exists, nobody can mark a game as one; permission, provenance and
  recommended templates are missing.
- **Categories, tags, Discovery, search, public card, my games, quotas**: none exist.
- **Market gates of the adult functions H4 adds** (publish, templates) and a public read of what a
  place asks for, which the declaration screen needs to name the age before it is answered (D-042).

## Deliverables

   in both repos. Validator at 0.
2. `D-NN` decisions for anything structural the specification leaves to the agent; any product hole

3. Task briefs `tasks/T-401.md`… and the H4 board in `PLAN.md`, each self-contained enough for a B-
   or C-tier session, each listing the WCAG 2.2 AA checks for the screens it builds, and a closing
   task that verifies H4 the way T-307 verified H3.
