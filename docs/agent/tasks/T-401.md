# T-401 — The versions split and lifecycle

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** backend · **Milestone:** H4 · **Requires:** T-400 (design)

## Goal
Split the versions code out of `play/session` into `play/versions`, give the four version
conditions their distinct homes (D-045), make finishing a version an explicit act apart from
publishing (P04§1-2), let the owner choose the version new Sessions use or return to a previous one
(P04§5), and move the build queue onto txqueue (D-050). The old publish flow and endpoint are
retired. P04, P15§2 and D-045/D-050 govern.

## Read first
- Site data: the `play.versions` domain with its re-homed tables (`play_games`,
  `play_game_versions`), the new `game.games` columns (`chosen_version_uuid`,
  `offered_publication_id` is T-402's), `game.game_version_choices`, the operations
  `game.check-ownership`, `game.choose-version`, `game.resolve-playable-version`,
  `play.versions.list-versions`, `play.versions.read-version-facts`, the changed `freeze-version`,
  `run-build`, `game-lifecycle` and `play.session.create-session`, and the flows
  `finalize-version`, `switch-current-version`, `list-game-versions`, the changed `create-session`
  and the retired `publish-game`.
- `DECISIONS.md` D-045, D-050; P04§1-3,§5 and P15§2 in full (`docs/definitivos/md/`).
- `playhoot/AGENTS.md`; `utils/txqueue` as built (D-014); how `orchestrator/publishgame` and the
  `play/session` version code work today.

## What to build
1. **The package split**: `play/versions` with `usecases/` and `workflows/` for drafting, building,
   assets, previews, freeze and the new reads; `play/session` keeps Sessions only. Table ownership
   follows (same table names). `play_games.current_version_id` is dropped.
2. **Finalize** (`finalize-version` flow): find the editable version → CheckPublication blockers →
   claim the release → freeze with assets → complete → by default record the choice in game. The
   release loses its `visibility` column; `games.visibility` is dropped; `games.published_at` stops
   being written here (T-402 writes it at first approval). `POST /v1/games/{g}/versions/finish`
   replaces `POST /v1/games/{g}/publish`.
3. **The choice**: `games.chosen_version_uuid` + `game_version_choices` (game repo), written by
   `game.choose-version`; `switch-current-version` flow with `read-version-facts` validating the
   version; `PUT /v1/games/{g}/versions/current` (choose, return to a previous one, or clear =
   unavailable). Existing Sessions never move (P04§3).
4. **Version resolution at create-session** (D-045): `game.resolve-playable-version` (owner →
   chosen; others → T-402's offered version — until T-402 lands, non-owners of a game published
   under the old model keep playing through a compatibility read the task defines, or simply: the
   old `published` flag keeps answering until T-402 replaces it; say in the Result what was done);
   `play.session.create-session` takes the version uuid and verifies EXECUTABLE.
5. **Version list**: `play.versions.list-versions`, `game.check-ownership`, the composer
   `list-game-versions` flow, `GET /v1/games/{g}/versions`.
6. **Builds on txqueue** (D-050): a play domain queue; applying a change enqueues `run-build` keyed
   by the version; the handler builds the newest QUEUED revision; supersession unchanged through
   build rows; the in-process wake signal and 5 s poll go.
7. Migrations edited in place (METHOD §6); new identity operations for the new endpoints in the
   catalog and its test. Site data → `implemented`, corrected where building taught otherwise;
   validator at 0.

## Acceptance criteria
- `go build ./... && go vet ./... && go test ./...` green (DB tests included); `TestH1Walkthrough`
  and `TestH3Deletion` stay green.
- Tests cover: finishing with and without the default choice, a blocker refusing the finish,
  returning to a previous version without touching a live Session, clearing the choice
  (unavailable), resolve-playable-version for owner and non-owner, a build run through the queue
  and superseded correctly, idempotent retries of every flow.
- Validator at 0; commit and push. **Say in the Result that the creator must recreate the local
  database** (dropped and moved columns).
