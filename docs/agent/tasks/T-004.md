# T-004 — Document the existing backend

**Tier:** C (Sonnet · medium) · **Size:** L · **Repos:** backend · **Milestone:** H0 · **Requires:** T-001, T-002

## Goal
Load into `playhoot/docs/system/` everything that exists today in the backend, in state `implemented`, so that the creator sees the current system and later designs start from a reliable map.

## Read first
- `docs/agent/designs/system-docs.md` §3 (data model) and §6.
- `docs/agent/inventory/backend-domains.md` and `backend-entrypoints-infra.md` (§1, §2): they are the script. **Verify against the code** whatever is loaded; if the inventory and the code differ, the code governs.
- The T-001 seed data as an example of style and level of detail.

## What to load
- **Tables** (47): identity 14, game 10, play 23 — columns, indexes, how their history is tracked, references.
- **Operations** exposed by `identity`, `game`, `play/session`, `play/runtime`: effect, what they read and write, main rules, limits, lifecycles (session, version, build, edition, release, preview, login attempt).
- **Flows** of `orchestrator` (create session, create game, draft changes, publish, open edition, AI link, preview…) and `composer` reads, with their steps per domain.
- **Endpoints**: 80 REST routes, 4 WebSocket, 22 MCP tools, with their access and what they invoke.

## Rules
- Creator's level of detail: no helpers, DTOs or signatures. Short sentences.
- One data file per domain (and per subdomain if it exceeds ~400 lines).
- What is half-done or unused (domain inventory §1.7, §2.7, §3.9) is documented as is in `summary`, without dressing it up.
- Product code is not changed.
- Work by domain and validate after each one (`node tools/validate-docs.mjs`). Pause point for usage after each domain.

## Acceptance criteria
- Validator at 0. Site counts match the code: tables from the migrations, registered routes, MCP tools.
- Sample of 10 random entities checked against the code, noted in the result.

## Result

Loaded into `playhoot/docs/system/` as `implemented`, all cross-checked against the current code:
- **Tables (47)**: identity 14, game 10, play 23 (9 in `play.session`, 12 in `play.versions`, 2 in `play.replay`).
- **Operations (46)**: the exported surface of `identity`, `game`, `play.session`, `play.versions`, `play.replay` and `play.runtime` (play's runtime has no tables of its own; `play.versions` and `play.replay` had to gain operations too, since the endpoint and flow catalogs needed something to invoke).
- **Flows (added 10, converted 3)**: `create-game`, `start-creation` and `external-ai-edit` moved from `planned`/`touches` to `implemented`/`steps`, matching what the code actually does (no compliance, plan, budget or moderation checks yet — already recorded in `GAPS.md`, untouched). Added `edit-draft`, `ensure-draft`, `start-draft-preview`, `game-ai-link`, `publish-game`, `open-edition` (orchestrator) and `ai-link-status`, `read-draft-workspace`, `simulate-draft`, `browse-game-templates` (composer) for the remaining orchestrator/composer groups the task asked for.
- **Endpoints (106)**: 80 REST + 4 WebSocket + 22 MCP tools, each with its access level and what it invokes.

Validator: `node tools/validate-docs.mjs` → 0 errors, 301 entities.

Sample of 10 checked directly against the code: `identity_sessions` and `game_releases` columns (migrations), `play_game_version_builds` columns (migration), the `GET /v1/games/{g}/draft/build` route (`api/games/handler.go`), the 22 MCP tool names (`api/mcp/tools.go` + its own test), `orchestrator/gameauthoring.Publish` and `.CreateAILink`/`.RevokeAILink` (exist as described) — all matched.

One correction found along the way: `inventory/backend-entrypoints-infra.md` records the resource-grant / asset-upload-URL work as uncommitted; it is in fact committed (`11f1eee`, an ancestor of `HEAD`). Fixed the wording in the loaded data (dropped "work not yet committed"); the inventory file itself is left as a dated snapshot, not corrected.

Discovery's template catalog stub (returns empty lists) is documented as-is inside `browse-game-templates` and `game.find-template`'s summaries, without dressing it up.
