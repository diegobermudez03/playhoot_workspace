# T-402 — Publication, review, withdrawal and block

**Tier:** B (Opus · medium) · **Size:** L · **Repos:** backend · **Milestone:** H4 · **Requires:** T-401

## Goal
Make publication a reviewed combination: the request that freezes version + card + assets into a
snapshot, the moderation review core that approves or denies exactly that, the offering that keeps
the previously approved combination public while an update is reviewed, and the three distinct ways
out — unpublish, delete, administrative block (P04§4-6). The creator is notified of outcomes.
P04, P13§3-6 and D-046 govern.

## Read first
- Site data: `game.game_publications` (+ status changes, tags snapshot), `game_offering_changes`,
  `game_blocks`, the new `game.games` columns, the operations `game.request-publication`,
  `apply-review-decision`, `set-offering`, `delete-game`, `apply-block`; the whole `moderation`
  domain (review tasks, measures, its five operations); the flows `request-publication`,
  `review-publication`, `withdraw-game`, `block-game`; the endpoints under `/v1/games/{g}/…`
  (publication, unpublish, republish, delete) and `/admin/v1/reviews`, `/admin/v1/games*`.
- `DECISIONS.md` D-045, D-046; P04§4-6, P13§3,§5-6 in full; P02§1 (publish is an adult function).
- D-016/D-038 (the market gate as built; the matrix gains the `publish-games` function here),
  D-018 (the notification types `discovery-review` and `discovery-restriction` already exist).

## What to build
1. **The request** (`request-publication` flow): market gate (`publish-games`, seeded in the matrix
   migration for the open markets like create-games) → `read-version-facts` → the snapshot row
   (mandatory private-content declaration = "no", category required, academic as a claim, images by
   object key, facts copied) → `moderation.submit-review`. A new request supersedes the pending one.
2. **Moderation's birth**: the domain package with `moderation_review_tasks`,
   `moderation_review_status_changes`, `moderation_measures`; submit / decide / cancel / list /
   record-measure per the site data. Its own domain queue for the notify tasks.
3. **The decision** (`review-publication` flow): decide → `game.apply-review-decision` (first
   approval writes `games.published_at`; snapshot category and the reviewed academic mark land on
   the game; offering recomputed per D-045; moot guard when the game died meanwhile) → notify the
   creator (type `discovery-review`, the denial carries the note).
4. **The ways out** (`withdraw-game` flow): `set-offering` (unpublish / republish, approval record
   untouched, D-046), `delete-game` (single game, sessions and replays untouched), pending review
   cancelled. Endpoints per the site data.
5. **The block** (`block-game` flow): `record-measure` → `apply-block` (nobody plays, no requests,
   no copies; running Sessions continue) → cancel pending review → notify the owner
   (`discovery-restriction`, necessary). Admin endpoints block/unblock + `admin-find-games` minimal
   read behind `GET /admin/v1/games`.
6. **resolve-playable-version completes**: non-owners play the offered publication's version; the
   T-401 compatibility read goes. `check-playability`'s remaining callers move over; the old
   operation is deleted.
7. Analytics events (`publication-requested`, `publication-decided`) from the owning transactions.
   New identity operations in the catalog and its test (publication at account level; reviews,
   taxonomy and blocks at admin level — no step-up: recorded, reversible acts). Migrations edited
   in place. Site data → `implemented`; validator at 0.

## Acceptance criteria
- Backend checks green, walkthroughs included.
- Tests cover: a private game never creating a review task (P13§3); submit → approve → offered;
  an update under review keeping the previous combination offered (P04§4); deny with note; a
  superseded request; card edits not touching the snapshot; unpublish keeping the approval and
  republish needing no review; delete leaving a running Session alive; block refusing the owner,
  cancelling the pending review and notifying; the moot guard; `declaration_required` on publish
  without a declaration; idempotent retries throughout.
- Validator at 0; commit and push. Say whether the creator must recreate the local database.
