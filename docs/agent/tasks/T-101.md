# T-101 — Transactional queue and DLQ admin

**Tier:** B (Opus · medium) · **Size:** M · **Repos:** backend · **Milestone:** H1 · **Requires:** T-100

## Goal
Build the shared `txqueue` package: the one way to do async work in every domain, with dead-letter handling and its admin surface.

## Read first
- `playhoot/docs/system/packages.js` (txqueue) and flows `admin-dlqs`, `manage-dead-task` in `flows.js`.
- `DECISIONS.md` D-010 and V-02; `playhoot/AGENTS.md` (architecture rules, standards).
- The site endpoints `GET:/admin/v1/queues/dead` and the retry/cancel pair in `api.js`. Admin access needs T-102's token: until then protect the endpoints at admin level and test with a stubbed authorizer the way existing admin-less operations are tested.

## Deliverables
1. Package `txqueue`: migration helper that creates `<domain>_queue_tasks`; `Enqueue(tx, type, payload, runAt, idempotencyNote)`; worker with SKIP LOCKED claim, V-02 backoff, `dead` after max attempts; `cancelled`; completed rows deleted; periodic tasks re-enqueue themselves.
2. Handler registration per task type by the owning domain; a separate registration point the orchestrator uses for cross-domain types (`notify`, `analytics-event`, `spend-event`) — the types exist as constants now, their handlers arrive with T-105/T-106/T-107.
3. Registry over every created queue; admin operations list dead / retry / cancel; the three admin endpoints.
4. First real use to prove it end to end: a trivial periodic housekeeping task in one existing domain (e.g. identity's sweep of expired unused resource grants, today done inline on create).
5. Docs: txqueue package, the two flows and three endpoints to `implemented`; service/queue/processor separation stated in the package entry.

## Acceptance criteria
- `go build ./... && go vet ./... && go test ./...` green; worker tests cover retry, backoff, dead, cancel, idempotent re-run, two workers not double-claiming.
- Validator at 0.

## Out of scope
The consumers of the cross-domain types (T-105…T-107). Real outbox/queue infrastructure.

## Result
Done 2026-11-15 (Opus · medium).

- `utils/txqueue`: `Migration(id, domain)` helper, `Queue.Enqueue(tx, type, payload, runAt, idempotencyKey)`, worker (`Run`/`ProcessDue`) with SKIP LOCKED claims under a lease, V-02 backoff with jitter, `dead` after max attempts or a permanent failure, completed rows deleted, periodic tasks scheduled once and re-enqueued on completion. `Handle` / `HandlePeriodic` for the owning domain; `HandleDelivery` for the orchestrator, limited to `notify`, `analytics-event`, `spend-event` (constants only; their handlers come with T-105…T-107 and their tasks wait pending until then). `Registry` over every queue with list dead / retry / cancel. Details and choices in D-014 and V-05.
